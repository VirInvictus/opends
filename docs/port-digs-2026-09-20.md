# Port digs, 2026-09-20 (four EXE/data mines for the Godot port)

Four read-only mining waves run against DSUN.EXE, RESOURCE.GFF, and
the save fixtures, aimed exactly at the open POLISH items. Full
evidence (offsets, byte dumps, correlation scores) was returned with
each report; this file is the distilled, durable record. The Godot
port lives in `port-spike/`; implementation notes here are the digs'
wiring recommendations, not yet port state.

## 1. Inventory centre figure (POLISH item 1: SOLVED)

- Art: `RESOURCE.GFF` `BMP ` ids **20000..20013** - fourteen
  single-frame standing figures, one per race/gender combo, DS1 RLE,
  PAL 1000, index 0 transparent. K'tarchek is 20013 (79x95).
- Ground truth: BMP 20013 decoded and diffed against
  `oracle/inventory_13500_ktarchek.png` = **100.0% match** at board
  (81,49), i.e. card offset (6,13) over blank card BMP 13005 in the
  APFM/13200 card (75,36) 90x125.
- Selection rule: `id = 20000 + (race-1)*2 + (gender-1)` (the
  chargen UI-list index); corroborated by the EXE preload loop
  (DS1 file 0x72E5D..0x72ED9: `add ax,0x4E20`, `cmp si,0xE`,
  cumulative art cache at ds:0x5485; DS2 mirror at 0x7B58E). The
  runtime per-character index derivation is the one unproven link.
- Ruled out: BMP 13002/13003/13004 (opaque plates), PORT chunks
  (upscaled 32x32), world sprite 2097 (party box only).
- Wiring: export figure_20000..20013; `party_data.gd` already
  carries race_i/gender_i; the regenerated `bg_13500.png` needs the
  baked figure in-painted out so the live layer is the only one.

## 2. Spell USE wiring (POLISH item 2)

- Known spells: **SPST = one byte per spell id 1..138, 1 = known**.
  Party mirror is `DARKRUN.GFF SAVE/19` (552 = 4x138, party order),
  PSST mirror SAVE/20 (4x34), PSIN mirror SAVE/21 (4x7). Roster-side
  CHARSAVE.GFF carries per-slot SPST (ids 15..19, 138 B) - all zero
  in the factory install (runtime-initialized). DS2 differs
  (LSB-first bitmask, `known_level << 1` PSST values).
- The 0x4512C table (raw DSUN.EXE file offset, 138 x 7 bytes):
  byte 0 = level 1..5; bytes 1..3 = u24 LE class-eligibility
  bitfield (9 distinct masks; bit semantics derived and verified
  against both fixture druids' SAVE/19 sets: bit 0 wizard family,
  bit 1 priest family, bits 2-5 cleric elements Air/Earth/Fire/
  Water, bits 6-9 druid variants, bits 14-17 ranger variants,
  bit 19 generic MAGE, bit 20 generic CLERIC; dust = air|earth,
  quicksand = earth|water); byte 4 = 0x00; bytes 5..6 = u16 LE
  DGROUP offset of the display name (string pool at file 0x48960;
  129/138 match the SPIN names, 9 engine abbreviations).
- USE screen = WIND 11500 spell-select mode: the grid is the sheet's
  35 right-panel cell APFMs **11213-11247** at rows
  y=42/62/82/109/129, cols x=148..262, pitch 19x20 (9px divider band
  before row 4); content = known SPST AND family matches the class
  bar AND level byte equals the LEVEL page; icon = `21000 + id`.
  Bars: BUTN 11319 (42x12 at 132,157, icon 11109) = class
  ("CLERIC" even for a Druid - divine family), BUTN 11320 (48x12 at
  173,157, icon 11110) = "LEVEL %d". Learn screen 17500 is a
  different flow (OVR9 stub2, 21 cells at x=28..142, click LEARNS
  via 0x500:0x43).
- Unproven: LEVEL bar value semantics (page vs char-max formula
  `[0x4AEC] = (OVR10 stub1+1)>>1`); whether the grid hides spells
  above caster level; memorized-vs-castable model; exact CLERIC
  cycle order.
- Wiring: export `spells_ds1.json` (level, class_mask, name, icon
  id per spell; psionic list from the 34x8 table at 0x44F90);
  replace fake `"spells"` dicts in `party_data.gd` with a 138-byte
  `known` array; `save_io.gd` gains SAVE/19/20/21 on write and read
  (keeps port saves engine-loadable); three new verified rows for
  `tools/save-inspect/syms/save-fields.toml`.

## 3. Popups 14000-14002, interact 3020, dialogs 3007/3008 (POLISH item 4)

- 14000: backdrop `bmp14000.png` (146x67, bakes outline, stone,
  sunken title strip, drop shadow). Oracle placement **(92,71)**,
  not centred. Title glyphs at plate-rel (9,6), light ink on the
  sunken strip; line labels dark ink 2px inside the bar, caps at
  bar_top+2; the runner blanks AND disables unused lines (disabled
  = not painted - the oracle shows only the used bars); lines
  hard-truncate at 20 chars; explicit first-letter array;
  keyboard first-letter per line; ESC only when the caller allows;
  X (10308) pushes the allow-close flag. Runner 0x54F21, opener
  0x54DB0; low-memory fallback WIND 14001 (137x56, buttons 14005-7,
  no bg art shipped). Strings: `EXIT: SAVE GAME?` 0x4965B,
  `EXIT GAME?` 0x49650, `SAVE` 0x4966C, `QUIT` 0x49671,
  `CANCEL` 0x49676, `LOAD/RESTART GAME` 0x4967D (the correct
  load/save popup title).
- 14002: 91x44 party ADD/DROP slot picker (six 18x18 APFM cells
  11213-11218, BUTN 11305 + X 10308); opened at 0x55718 when a
  clicked member has combat+0x1C != 1. 11305's action unproven.
- 3020 interact strip: 92x77; talk 15306 (ICON 15105 mouth), steal
  15308 (15107 hand+coin), give 15307 (15106 open hand), INFO
  15309 (15109; chunk text has a stray leading NUL, real label
  INFO). All three action buttons start disabled, enabled by a
  capability mask in di (bits 0x4 talk, 0x1 steal, 0x10 give).
  Opener 0x5F078; APFM 15200 ships 145x87, larger than its window
  (engine clips). Capability-mask source unproven.
- 3007 dialog: 318x58 at runtime (0,0) (chunk says (10,0); the
  engine overrides, same as 10500). Portrait BUTN 2090 (frame 48x47
  + 32x32 face slot fed by the PORT chunk via dialog-print cmd 1),
  EBOX 4002 text area (236x46, 50-char line cap), up-arrow 2093 and
  MORE 2094 (ICON 12100 vertical MORE). Fed by the dialog print
  service (cmds 0/2/4 append, 1 portrait, 3 open/refresh - open
  verified at file 0x7D3CE). The 0x48 MENU picker renders a dynamic
  `MENU %u` chunk inside 3007.
- 3008 choice subwindow: same shell; five 300x10 bars 2076-2080
  (ICON 12102-12106); opens at **(0,140)** (file 0x7D530,
  `packed_xy 0x8C0000`); MORE 2096 enabled iff dialog line count
  (ds:0x5503) > 5. Bar-population mechanism still an open hole.
- Exporter needs nothing new (winds.json already carries all six
  windows and every referenced ICON face).

## 4. Effects screen and overhead map (POLISH item 3)

- Effects = WIND 11500 effects mode (game-menu 11306, handler
  0x7E8A7; E hotkey). Backdrop BMP 11000, title BMP 20075.
  Conditions: SAVE/5 combat sub-blocks (58 B), status byte at +28
  (SAVE/6 has NO status field - correction), indexed into the
  9-string table at DSUN.EXE 0x49bb0: `New, Okay, Stunned, Out
  Cold, Dying, Dead, Animated, Petrified, Gone` (so Okay = 1, and
  `save_io.gd` writing status 0/1 is already engine-correct). Active
  effects are runtime-only (DS1 record 114, 10-byte records at
  +0x106, count DGROUP [0x1e24]); names via the 70-entry table at
  0x4a94c (`Acid` .. `Prayer`). Empty state is otherwise built;
  remaining: light button 11306 while in effects mode, draw the
  region-name plate (BMP 5016 at (215,4), shared with the map),
  replace hardcoded "Okay"/"Dead" strings with the 9-string table,
  exporter addition `generated/ui/strings.json`. Non-empty panel
  layout needs a dig of 0x7E8A7.
- Overhead map: plate = BMP 10003 (265x178, interior transparent;
  exported as `generated/ui/map_10003.png` by `export_items.py`).
  The automap bitmap is ~96x70 px at board ~(66.5,29.5) (plate
  interior's top-left, tile (0,0) anchored - NOT centred), scale
  ~1.5 px/tile (least-squares 1.44-1.49 on three anchors). Cell
  paint: open (GMAP 0x00) -> flat tan **PAL 42[107]** (210,161,137);
  blocked -> flat orange PAL 42[97]; wall-index cells draw their
  WALL sprite art through PAL 42, not font glyphs. **Automap
  palette = GPLDATA `PAL <region_id>`** (PAL 42 = Arena; all top-14
  oracle colours within <=1.4 RGB). Doors read as floor once opened
  (GMAP 0x40+0x80 clear at runtime). Region 42 = RGN2A.GFF "Arena",
  41 = RGN29.GFF "Slave Pens". No party arrow identifiable in the
  capture; DS1 ships "CENTER ON LEADER" (10313) instead.
- The WIP minimap (tile-atlas centre colours at 2:1) cannot match:
  the automap is flat GMAP-flag fills + wall sprites through the
  region palette. Recommended path: precompute the 96x70 map bitmap
  in `export_region.py` (flat fills + bottom-anchored wall sprites
  via its existing placement rule) and blit at plate-local (40,19);
  sample the red scale-pattern backdrop from the oracle capture
  (its art id is unproven; base colour = PAL 42[97]) like
  `bg_13500.png` was made; keep the demo's 3-tile tunnel patch out
  of the map data (`blocked_rows` currently bakes it).
- Still unproven: automap window rule (origin-anchored vs
  leader-centered 64x47; one DOSBox capture of the Slave Pens map
  settles it), stands/rock-edge cell paint, region-name text source
  (no region-name strings anywhere; DS1 predates RNME), the
  red-pattern art id.
