# Port digs, 2026-10-07 (mineout closure: the open-hole sweep driven to verdicts)

Mineout sessions 2-3. The campaign's completion bar (PROMPT-mineout
section 1) needed three things after the data phase: the open-hole
sweep's 26 remaining hits driven to resolutions or written
closures, the Mel-name adoption batch, and the final record. This
file records the digs behind those closures. Seven research agents
in two waves (GLM-5.3, main thread wrote everything); every
verdict below carries its evidence so the docs that cite it stay
checkable.

## 1. The Mel library, named and adopted (ovr-map 0.3.6)

The RBRN dig's four cited names (port-digs-2026-10-06.md 2) are
now eleven verified rows in `tools/ovr-map/syms/ds2.toml`
(`mel_error`, `mel_register_graphic_shutdown`, `mel_open_animation`,
`mel_animation_manager`, `mel_break_loop_and_branch_to`,
`mel_branch_to`, `mel_measure_wait`, `mel_beat_wait`, and the data
cells `gmel_indirect_control_array`, `gmel_current_branch`,
`gmel_branch_taken`), all with `dso_source`.

The method upgrade that made the batch provable: the DSO checkout
ships `tools/mdark.bin`, a disassemblable 32-bit flat image of the
DSO v1.0 client, and its Mel layer is intact (only AIL proper is
stubbed to `push ebp; mov ebp,esp; ret`). Disassembling mdark.bin
at the symbols.txt offsets yields real Watcom code whose behavior
matches DS2's 16-bit residents function-for-function. Version
strings: DS1 carries "Mel Real Mode Version 2.0.9b, 08/30/93" at
file 0x4c76c (the string the RBRN dig quoted), DS2 carries "Mel
Real Mode Version 2.2.7, 10/14/94" at file 0x50534 (DGROUP:0x3534,
referenced by `mel_error` at 0x3f01a), and DSO's client carries a
protected-mode 2.2.5. DS2 and DSO are adjacent versions, so
bodies match case-for-case (the animation manager's callback
switch, the branch pair's guard chain and four byte stores, the
wait pair's AIL call shapes).

What the batch pins for the adaptive-music story: the branch
consumer is `mel_animation_manager` (registered by
`mel_open_animation`), whose callback values 1..0x22 are exactly
the RBRN branch-id space; a branch write goes
`mel_break_loop_and_branch_to` / `mel_branch_to` -> the indirect
control array (DGROUP:0xa3a4, 128 bytes; ICA[0] = desired branch,
ICA[0x7f] = the loop-break flag the `[BF 75 7F]` NEXT events
consume) and `gMelCurrentBranch` (state segment 0x3e71:0xc28).
`mel_break_loop_and_branch_to` has zero static callers in the
shipped DS2 image: retained API, unused, consistent with DS2
content carrying no RBRN. DS1's twin validates the branch id
against a per-song branch-count table at DGROUP:0x1675 (stride 3)
before the same 1..0x22 gate; DS2's 2.2.7 dropped that check.
Neither EXE contains any sequence fourcc (RBRN/EVNT/TIMB/FORM
searched as bytes and word immediates): the .XMI form parser is
behind the AIL ordinal wall, which mdark.bin stubs, so it stays
unnamed. `MelSeqPlaying`/`MelWaitSeqPlaying` candidates were
examined and rejected (the AIL status enum moved between 2.2.5
and 2.2.7; name assignment ambiguous, no rows forced).

## 3. The GPL VM behavior holes, all six resolved

Full addresses in the agent's evidence chains, distilled;
`docs/gpl-vm.md` carries the in-place updates.

- **Rand (0x52)**: the handler computes
  `accum = (rand() * (N+1)) / 32768` (signed idiv by 0x8000), and
  `rand()` is the classic Borland LCG (seed * 0x015A4E35 + 1,
  result = `(seed >> 16) & 0x7FFF`). Raw range 0..32767
  inclusive, so `gpl rand N` yields **0..N inclusive** (N+1
  outcomes). Correction: gpl-vm.md's "srand has ZERO callers" is
  false; three relocation-validated `srand(time(NULL))` sites
  exist (DS1 ovr13+1071; DS2 ovr11+1309 and ovr35+30). The stream
  is wall-clock seeded wherever those paths run.
- **Statroll (0x59)**: `roll = (rand()*20)/32768` (a d20 as
  0..19); **roll 19 is an automatic failure** (natural maximum
  fumbles; no crit); target = signed byte `party_base + who*stride
  + b + 0x19` (DS2 stride 49, DS1 stride 58, stat at +0x22) plus
  adjustment-table byte; **success iff target > roll**. The `a`
  operand indexes the adjustment table: DS1 at file 0x3eb10, DS2
  DGROUP 0x193f, identical 8 bytes (skill adj 20/0/-10/-20, stat
  adj 5/0/-5/-10).
- **Skillroll (0x58)**: `success iff (rand() % 100) < rating +
  adj`, overlay bodies byte-identical across games (DS2 ovr35
  entry 0xa0b, DS1 ovr38 stub 4). The rating helper's tables are
  static file data (DS2 skill base table at file 0x49bb0; row 0
  base chances `1c 12 0d 1c 12 17 4e fc`).
- **Menu (0x48) post-selection tail**: the chosen entry's target
  is **ring-pushed LocalSub-style** (through the same helper
  LocalSub uses: cursor VM:0x192 incremented, depth recorded,
  value stored at VM:0x295 + 2*cursor); execution continues at
  that offset. The wave-4 table's "accum = the chosen entry's
  target expression" is wrong in mechanism; the accumulator is
  untouched. Targets are evaluated at parse time (stored to
  VM:0x27d+2i), enables to VM:0x2f9+i; an invalid pick re-invokes
  the UI stub without a re-parse; label/enable arrays are never
  cleaned (overwritten by the next Menu).
- **Passtime (0x30) and Continue (0x2b)**: both bodies were
  statically readable all along through the segtab. Passtime adds
  `N * 60` seconds to the 32-bit game clock at **VM:0x35b** (a
  cell inside the VM state segment itself, previously
  undocumented); Continue is a press-any-key page break ("Press
  continue" / "Continue" strings, then a modal wait pump).
- **The stop flag (VM:0x326)**: no overlay ever writes it
  directly. Four direct writers per game, all resident (three
  clears in the run/flush services, one standalone setter at DS1
  0x98c9 / DS2 0xc5ae). Overlays stop the VM through that setter:
  the GlobalRet-at-depth-0 unwind, ExitGpl, Fight, Zero, an error
  wrapper, and overlay sites that flush UI, optionally print
  **"BAD GPL EXIT"**, then call it.
- **The resume path does not exist.** Complete caller inventory:
  run_gpl_script has nine resident far callers per game (the
  trigger-record walkers and services) plus the ovr0 session-init
  (99, 0, 2); the executor is called only by run_gpl_script's
  wrapper and GlobalSub. The `chunk_id = 0` branch is a full VM
  state reset that returns without executing a single opcode, and
  no static caller passes 0. Everything runs synchronously inside
  the RunGplScript call frame; modal UI nests inside handler
  calls. The suspected "dialog completion, overlay-side"
  re-entrant is refuted by construction.

## 4. The GPL VM data model, all four resolved

- **GNAME is static.** The 13 far-pointer slots at VM:0x000..0x03b
  are file-backed and MZ-relocated (13/13 reloc targets verified
  per game), identical in both games: GNAME[32..44] point at
  GSTATE mode/x/y/aux/region, the six current-object registers
  (0x369/0x367/0x365/0x363/0x361/0x35f), the time counter 0x35b,
  party money 0x357, and the combat-state marker 0x35f's word
  (constant 0x209 written at combat init). The bytecode examples'
  GNAME[38]/[39]/[40] are literally VM:0x367/0x365/0x363. The
  gpl-vm.md premise "runtime-capture territory" is disproven, and
  with it the blitz box's GNAME[39] item: GNAME[39] = VM:0x365 =
  event object B, written only by the trigger-fire variants
  (DS1 0x9161/0x9299/0x93e0/0x9567 and their DS2 twins) and the
  combat "activate" service.
- **The second stream selector is the chunk-type key.** VM:0x195
  holds the active chunk TYPE (0x197 the id; gpl-vm.md had the
  two roles swapped, corrected), written at exactly two sites per
  game (cache hit / cache load), reached only through SetContext
  from run start, GlobalSub, and GlobalRet restore. The switch
  condition is purely the fast-path key mismatch; type 1 loads
  'GPL ', type 2 loads 'MAS '. That is the whole "second
  stream".
- **Current-object register producers, complete**: 0x369 (current
  combatant) is cleared by combat-driver init and updated by the
  object-rebind service; 0x367 (event object A) is the busiest,
  written by the three trigger-fire shapes, the dialog/talk path,
  and six orders/movement services; 0x365 (event object B) only
  by trigger-fire variants and the activate service; 0x363
  (current/query object) by Getparty, trigger-fire,
  nearest-search, the MONR encounter spawner, combat driver, and
  the picture module; 0x361 (OTHER) by Setother and the activate
  service; 0x35f by exactly one writer, combat-driver init's
  constant 0x209.
- **The DS2 Request arms are corrected**: the pair-carrying arms
  are **5/18/22/23/24/40/41/49** (not 32; 20/21 route elsewhere),
  each applying one of eight module-35 stub services (activate
  bit toggle, entity field set, status-router set, status clear
  with the >=0x71 whole-list form, party-record byte set, entity
  target set, combat-only action queue, quantity set), plus a
  ninth service outside the eight: arm 53 computes the object's
  tile center and calls the placement primitive through a module-32
  stub. The "resident function pointers" are overlay-stub
  pointers relocated through the per-module tables. Arms 31/32
  call genuinely resident functions (bit OR/AND-out in a
  0x62 x 0x80 per-chunk flag matrix).

## 5. The overlay loader's §8 items: five resolved, one partial

Full field maps and addresses distilled into
docs/overlay-formats.md 8; the headline facts:

- **DGROUP[0x114:8] (overlay file base)** is written once, by the
  overlay manager's init during Borland C0 startup (registered in
  the FID table as a relocated data pointer): open the EXE by its
  own name, compute `image_end` from the MZ header, **align up to
  16**, seek there, verify FBOV, store `align16(image_end) + 16`.
- **The INT 3Fh install site is found**: the manager's
  get/set-toggle (DS1 0x3ba73, DS2 0x40190) reads the vector
  number from DGROUP:0x111 (0x3F on disk) and uses DOS AH=35h/AH=
  25h with operands from DGROUP words, which is why every
  immediate-pattern search missed it. The survey's
  `mov [cs:0x2c4],dx` is real but unrelated: it parks the C0
  aux-data segment for the abort-message printer.
- **Segtab word3**: class-3 records always 0; class-4 records are
  `(size+1) & 0xffff` in all 14/14 cases per game (unifying the
  0xffff BSS markers as the wrap case); class-1 remains a
  TLINK-internal build-layout id with no runtime consumer
  (eliminated: not an ordinal, not the reloc count, not
  size-derived), closed as linker bookkeeping.
- **DGROUP:[0x86]** is the VROOMM module-state notification hook:
  default body a bare `retf` at the C0 segment, called with
  ax=8 (cold load) / 0 (warm) / 1 (extended-memory load) /
  ax=bx=0xffff (init restore). No writer anywhere; it stays
  do-nothing in both shipped games.
- **The resident-set policy is fully decoded**: [0x118] is the
  trim threshold (span>>2), [0x11a] the minimum-paragraph floor,
  [0x120] the allocation pointer, [0x122] a warm-restart chain
  head that is never written (the warm-restore path is inert as
  shipped), boot buffer = 2*max_module_paragraphs + 1; compaction
  repacks downward from the high bound, the LRU head is evicted
  when unlocked.
- **The raw-call reconciliation**: 19 resident raw
  `0x2460:0x4a4` sites in DS1 (not 14 as documented; DS2's twin
  is also 19), all boot-time or resident-service code that cannot
  live in an overlay; the 96 overlay-side sites carry the same
  target through the per-module fixup regime. Counts corrected in
  dsun-exe-survey.md and dsun-exe-re.md.

## 6. The UI-mode service is the cursor mode (named, both games)

DS2 `0xB0:0x2535` and its true DS1 analog `0x88:0x2927` are
**GuiSetCursorMode** (the DSO table names it; DS2 dispatcher DS2
0x2247D, DS1 0x1F089, structural twins). The enum:
**1 = MOVE** (menu buttons 10310 "MOVE CURSOR"), **2 = LOOK**
(10311), **3 = a spell cast is pending** (the cursor becomes the
per-character spell-target bitmap; all four DS2 mode-3 sites are
guarded by the is-a-spell-pending stub), **4 = ATTACK** (10312),
**5 = cast-targeting** (set by the spell-picker after choosing a
spell with a non-self target; the input dispatcher's mode-5 arm
selects among five per-target-shape callback tables). Mode 1 also
gates party-member click movement; mode 3 alone allows
ground-targeting. screen-flow.md's DS1 "analogs" 0x4F8:0x84 and
0x508:0x57 were misidentifications and are corrected (they are
GetClassLevel, 62 sites pushing class ids, and GetStateStat,
12 sites pushing stat selectors).

## 7. The DS2 item-template fields resolve; DS1's "authoring
## residue" column turns out to be live DS2 data

The engine's actual template table is **'ALL ' chunk id 4** in
DS2's OBJEX.GFF (102 rows x 15 bytes; the RDFF template blocks
match it 87/87 at the same index, so the blocks are serialized
copies), consumed through the far global [0x19cd] with stride 15.
Field verdicts: **+2 = weight** (backstab gate <= 40; dual-wield
gate > 30 = "Cannot use two heavy weapons"; melee-only getter),
**+3 = breakage/damage threshold** (an item is damaged only when
the damage amount strictly exceeds +3; domain
{0,5,10,20,40,50,80,250,255}; DSO names BreakItem/BreakWeapon in
the family), **+6 = range** (compared against tile distance),
**+7 = attacks per slot in half-rounds** (the damage formatter
renders value/2 with a ".5" suffix; melee substitutes caster
level when range <= 1). Cross-game: DS2 +6/+7 equal DS1 IT1R
+10/+11 exactly, and DS2 +3 equals DS1 IT1R +6, the column
object-formats.md had resolved as DS1 authoring residue: it was
authored in DS1, ignored by the DS1 engine, and went live in
DS2's engine.

## 8. The UI-lane residuals (port-digs-2026-09-20) close

- **The automap is a fixed whole-region miniature.** No 64x47
  window and no leader centering: the map opens WIND 3004, blits
  plate BMP 10003 at (27,10), blits **BMP 20120 + region_id** at
  (67,30) (186x139 art covering the whole 128x96-tile region at
  16/11 px per tile, origin-anchored), then plots creatures:
  leader pixel colour 15, other creatures colour 240. No runtime
  cell paint exists (the tan/blocked appearance is baked into the
  art); the map draws zero text, so there is no region-name
  source to find (BMP 5016 is the resident member-name plate,
  unconnected). Click-to-travel inverts the same math.
- **14002 is the combat quick-cast strip**, not a party ADD/DROP
  picker (port-digs-2026-09-20.md 3 corrected, including the
  polarity: combat+0x1C == 1 opens the strip; != 1 jumps straight
  to the full 11500 spell-select). Cell handlers read the
  per-member quick list at [0x4AFD + member*30 + cell*2], check
  per-family per-level cast counters and combat silencing, and
  start the cast; **BUTN 11305 escapes to the full cast screen**.
- **The learn screen's LEVEL bar shows the browsed spell-level
  page**: `[0x4AEC]` is a byte initialized to
  `(preserver_level+1)>>1` (the OVR10 stub1 class arg is 0x0B)
  and cycles 1..max; the fill gate is `spell level == page` AND
  wizard-family mask AND not-already-known (SPST & 0xF). There is
  no per-spell caster-level comparison; above-page spells are
  hidden by the page clamp alone.
- **The class cycler order is MAGE -> CLERIC -> PSIONIC -> wrap**,
  skipping empty legs (labels ' MAGE'/'CLERIC'/'PSlONlC' at
  DGROUP 0x1240, so a Druid literally reads CLERIC). DS1 has **no
  per-spell memorization**: known = SPST; castable = per-family
  per-level counters at [0x4B08]/[0x4B11 + member*30 + level]
  (decremented on cast, printed by the "SPELLS TO CAST" header);
  the six quick-cast cells are an MRU list.
- **The one hole left open, closed as runtime-only**: who fills
  the cast counters (rest/level-up recalc) writes through
  computed pointers no static form-shape scan can pin. The
  capture that settles it is named in the docs: rest once under
  a DOSBox watchpoint on DGROUP:0x4B08, or diff a before/after-rest
  played-save pair for a 30-bytes-per-member SAVE chunk.
